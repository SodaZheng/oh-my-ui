# 质量门槛

## 结构门槛

- JSON 可解析，schema 版本受支持，revision 为正整数。
- 所有对象 ID 唯一；来源项目、场景关系、场景变体、页面实例和证据引用均可解析。
- 场景和场景分组由真实页面任务归纳生成；初始化模板不得预置固定分类，分组 ID、标题和文件名保持唯一。
- 每个来源项目有不依赖本地路径的稳定身份键、别名、独立项目画像、路由/组件账本和扫描覆盖分母。
- 每个组件都有适用、不适用、场景角色、组合关系、内容、布局、交互、状态、知识状态和可信度。
- 每个场景都有唯一语义键、完整语义画像、适用/禁用、页面形态、布局骨架、区域组合、组件配方、任务流、状态、来源、实例引用、知识状态和可信度。
- 每个页面实例都有唯一来源项目、关联场景、外壳、布局骨架、区域树、组件实例、任务流、页面状态、适配和五维覆盖状态。
- 场景与页面实例引用双向一致；页面形态索引从场景派生，不维护独立事实。
- 路由/页面与组件按来源项目分别报告覆盖分母。

## 语义门槛

- 场景中的页面骨架至少说明：推荐形态、进入后先看到什么、主次区域怎样排列、区域如何控制和反馈；页面实例再补充具体外壳、导航、画布、对齐、空间占用和状态变化。
- 每个组件实例至少说明业务角色、位置、空间方式、内容、交互、出现条件和局部状态。
- 场景组件配方区分必需、条件和避免，并说明每项的角色、位置、条件与理由。
- 组合项以功能目的命名，不以控件或代码实现命名。
- 正常无结果、请求失败、权限受限和对象不存在按实际相关性区分。
- 长时间任务说明离开后的返回入口和结果回收。
- 批量任务说明选择范围、风险确认和部分失败。
- 候选结论不能伪装成正式规范。
- 场景不能按标题去重；语义相同应归并，稳定差异应形成变体，同条件冲突应进入待确认。
- 多项目重复只能提高证据广度，不能自动升级为正式规范。

## 可见文档门槛

- 设计师只需打开导航、场景和组件目录，不必浏览隐藏目录。
- 不出现工程组件名、属性、路径、框架、代码块或技术调用关系。
- 不生成独立 `页面/` 目录；页面形态、来源项目和项目案例索引不复制场景正文。
- 颜色、像素和字号默认不在范围内；只有知识库明确收录且用户需要时才讨论。
- 有源码或运行证据的布局尺寸、间距、对齐和响应式阈值可以作为现状观察；无证据时必须标为未确认。

## 更正门槛

- 语义更正有预览和明确确认。
- 当前 revision 与预览 base revision 一致。
- 已检查直接关系和共享规则。
- 未修改对象保持稳定；变更历史只追加。
- 新证据与知识、派生视图、变更记录原子提交；失败不能留下孤儿证据。
- 默认拒绝删除既有对象或证据；来源扫描不得修改作用域外项目画像、页面实例和证据。
- 提交后重新生成可见文档并通过同一组校验。
