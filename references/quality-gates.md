# 质量门槛

## 结构门槛

- JSON 可解析，schema 版本受支持，revision 为正整数。
- 所有对象 ID 唯一；场景关系、页面形态、业务模块、证据引用均可解析。
- 场景和场景分组由真实页面任务归纳生成；初始化模板不得预置固定分类，分组 ID、标题和文件名保持唯一。
- 每个组件都有适用、不适用、场景角色、组合关系、内容、布局、交互、状态、知识状态和可信度。
- 每个场景都有适用、不适用、页面形态、区域组合、组件配方、任务流、状态、知识状态和可信度。
- 每个页面都有外壳、布局骨架、区域树、组件实例、任务流、页面状态、适配、五维覆盖状态、知识状态和可信度。
- `scanState` 有覆盖分母，不能只报告已成功扫描部分。
- 路由/页面与组件分别报告覆盖分母。

## 语义门槛

- 页面“长什么样”至少说明：应用外壳、导航和画布关系，进入后先看到什么，主次区域怎样排列，各区域包含什么设计组件，组件怎样对齐和占用空间，主要操作在哪里，状态变化发生在哪个区域。
- 每个组件实例至少说明业务角色、位置、空间方式、内容、交互、出现条件和局部状态。
- 场景组件配方区分必需、条件和避免，并说明每项的角色、位置、条件与理由。
- 组合项以功能目的命名，不以控件或代码实现命名。
- 正常无结果、请求失败、权限受限和对象不存在按实际相关性区分。
- 长时间任务说明离开后的返回入口和结果回收。
- 批量任务说明选择范围、风险确认和部分失败。
- 候选结论不能伪装成正式规范。

## 可见文档门槛

- 设计师只需打开导航和场景目录，不必浏览隐藏目录。
- 不出现工程组件名、属性、路径、框架、代码块或技术调用关系。
- 页面形态索引和业务模块索引只链接场景，不复制完整场景正文。
- 颜色、像素和字号默认不在范围内；只有知识库明确收录且用户需要时才讨论。
- 有源码或运行证据的布局尺寸、间距、对齐和响应式阈值可以作为现状观察；无证据时必须标为未确认。

## 更正门槛

- 语义更正有预览和明确确认。
- 当前 revision 与预览 base revision 一致。
- 已检查直接关系和共享规则。
- 未修改对象保持稳定；变更历史只追加。
- 提交后重新生成可见文档并通过同一组校验。
