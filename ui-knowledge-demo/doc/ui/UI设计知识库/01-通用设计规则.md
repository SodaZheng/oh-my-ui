# 通用设计规则

> 这里只保留跨多个任务场景成立的规则。项目实现只能贡献证据，不能自动成为通用规范。

## 先让用户识别当前任务

进入页面后，应先让用户知道正在处理什么、对象处于什么状态，以及当前最重要的行动是什么。

**适用：**

- 页面承载明确业务任务。
- 用户可能从多个入口到达同一页面。

**不适用或例外：**

- 纯浏览型内容没有可执行任务。

**来源项目：** UI 设计知识库分层示例

**知识状态：** 候选规律　 **可信度：** 低

## 区分没有结果与发生失败

正常没有数据、条件没有匹配、请求失败、无权访问和对象不存在必须根据真实原因分别解释，并给出不同的下一步。

**适用：**

- 主要内容由数据或权限决定。

**不适用或例外：**

- 结果含义无法由现有证据判断时，先保留未知。

**来源项目：** UI 设计知识库分层示例

**知识状态：** 候选规律　 **可信度：** 低

## 风险越高越需要影响说明

操作越不可逆、影响对象越多或后果越难恢复，越需要在行动前解释范围、依据和后果。

**适用：**

- 删除、驳回、发布、批量执行或其他高影响操作。

**不适用或例外：**

- 低风险且可立即撤销的轻量调整。

**来源项目：** UI 设计知识库分层示例

**知识状态：** 候选规律　 **可信度：** 低
