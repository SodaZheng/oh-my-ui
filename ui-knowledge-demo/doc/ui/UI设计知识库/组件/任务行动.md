# 任务行动

> 承载页面级或区域级的主要、次要和高风险行动。

**知识状态：** 候选规律　 **可信度：** 低

## 解决的问题

让用户理解当前可以做什么、影响什么，以及行动后的结果去向。

## 适用场景

- 页面或区域存在明确可执行任务。
- 行动与当前对象、范围或权限直接相关。

## 不适用场景

- 行动条件和影响尚不明确。
- 只读页面没有真实可执行任务。

## 在任务场景中的角色

- **条件查找与结果浏览**：进入创建、详情或集合处理；出现条件：结果支持后续任务时
- **单对象详情与状态处理**：执行对象当前状态允许的任务；出现条件：用户具备相应权限时
- **分步骤创建与编辑**：返回、暂存、继续和提交；出现条件：输入任务存在阶段或提交时
- **多对象批量处理与长任务跟踪**：提交共同操作；出现条件：对象范围与影响已确认时
- **失败、部分成功与恢复**：重试、修正、继续或返回；出现条件：异常仍有可恢复路径时

## 与其他组件的组合关系

- 与 **[状态反馈与恢复](../组件/状态反馈与恢复.md)** 触发后由状态反馈解释结果和下一步；条件：行动会改变数据或任务状态时

## 内容规则

- 行动文字描述结果，不只描述动作。
- 高风险行动同时说明影响范围和后果。

## 布局规则

- 页面级行动靠近任务标题，区域级行动靠近所作用的内容。
- 主次行动以位置、层级和文案共同区分。

## 交互规则

- 不可执行时说明原因，不能只表现为不可点击。
- 提交过程中避免重复触发。

## 组件状态

- **可执行**：行动名称、对象和结果方向明确。
- **处理中**：保持任务上下文并阻止重复提交。
- **不可执行**：说明权限、状态或完整性限制。
