# 审核决定

> 让用户基于充分依据做出有后果、可追溯的业务决定。

**知识状态：** 候选规律　 **可信度：** 低

## 解决的问题

把决定、理由、影响和结果组织为一条可理解的判断链。

## 适用场景

- 决定会改变对象状态或影响后续流程。
- 结果需要记录理由。

## 不适用场景

- 用户缺少判断依据。
- 任务本质是补充信息而不是做决定。

## 在任务场景中的角色

- **基于依据的审核与决定**：承载决定、理由、影响说明和提交；出现条件：用户已阅读关键依据时

## 与其他组件的组合关系

- 与 **[对象信息分组](../组件/对象信息分组.md)** 位于判断依据之后，并保持依据可回看；条件：决定依赖对象信息和风险时

## 内容规则

- 不同后果的决定分别说明影响。
- 理由要求与可追溯规则一致。

## 布局规则

- 决定区与关键依据保持明确阅读顺序。
- 高风险决定处于稳定且不易误触的位置。

## 交互规则

- 依据不足时不迫使用户决定。
- 对象状态变化后要求重新确认。

## 组件状态

- **依据不足**：指出缺失信息并暂停决定。
