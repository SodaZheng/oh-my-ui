# 页面任务标题

> 说明用户当前位于哪里、正在完成什么任务，以及页面级状态和行动。

**知识状态：** 候选规律　 **可信度：** 低

## 解决的问题

让用户在进入页面时建立任务、对象和返回关系的共同认知。

## 适用场景

- 页面承载独立业务任务或可从多个入口到达。
- 对象状态或页面级行动会影响后续操作。

## 不适用场景

- 短小覆盖任务已经由触发位置提供完整上下文。
- 重复标题只会占用空间，且没有新增状态或行动。

## 在任务场景中的角色

- **条件查找与结果浏览**：识别当前查找范围和页面级行动；出现条件：进入集合浏览任务时
- **单对象详情与状态处理**：识别当前对象和状态；出现条件：进入单对象任务时
- **分步骤创建与编辑**：识别创建或编辑对象；出现条件：进入较长输入任务时
- **基于依据的审核与决定**：识别审核对象和阶段；出现条件：开始业务判断时
- **多对象批量处理与长任务跟踪**：识别批量任务范围；出现条件：进入集合处理空间时

## 与其他组件的组合关系

- 与 **[任务行动](../组件/任务行动.md)** 与页面级主要行动保持同一任务层级，标题在左、行动在右；条件：页面存在明确主要行动时

## 内容规则

- 标题直接描述当前任务或对象，不使用内部模块代号。
- 副信息只保留会影响判断的范围、状态或返回关系。

## 布局规则

- 位于内容画布起始位置，并与首个主要区域形成清晰间隔。
- 标题信息优先于页面级行动获得空间。

## 交互规则

- 返回入口必须能让用户理解返回后的上下文。
- 页面级行动只保留当前任务最关键的一到两个方向。

## 组件状态

- **正常**：显示任务、对象或范围，以及当前可用行动。
- **权限受限**：保留任务识别信息，隐藏或解释不可用行动。
