# 状态反馈与恢复

> 解释处理中、无内容、失败、权限、部分成功和结果未知，并提供安全的下一步。

**知识状态：** 候选规律　 **可信度：** 低

## 解决的问题

让用户理解真实结果范围，保留任务上下文，并避免重复已经成功的工作。

## 适用场景

- 内容或行动存在异步、失败、权限或不完整结果。
- 用户仍有重试、修正或继续路径。

## 不适用场景

- 系统无法判断真实结果范围时，不伪造成功或失败。
- 短暂成功确认没有后续行动时不扩展为独立区域。

## 在任务场景中的角色

- **条件查找与结果浏览**：解释加载、无结果与查询失败；出现条件：结果集合无法正常呈现时
- **单对象详情与状态处理**：解释对象不存在、权限和更新结果；出现条件：详情内容或行动受限时
- **分步骤创建与编辑**：解释完整性和提交失败；出现条件：输入无法推进或提交时
- **基于依据的审核与决定**：解释依据不足、冲突与决定结果；出现条件：审核流程无法正常完成时
- **多对象批量处理与长任务跟踪**：解释任务受理、进度和部分完成；出现条件：批量任务进入执行阶段时
- **失败、部分成功与恢复**：作为异常与恢复场景的主要内容；出现条件：任务未完整成功时

## 与其他组件的组合关系

- 与 **[任务行动](../组件/任务行动.md)** 反馈行动结果，并把恢复行动放在可处理原因附近；条件：用户仍能继续处理时

## 内容规则

- 正常无结果、失败、无权、对象不存在和结果未知分别说明。
- 部分成功区分已完成、失败和仍在处理。

## 布局规则

- 局部状态出现在受影响区域，全局结果在页面任务层呈现。
- 恢复行动紧邻原因和影响范围。

## 交互规则

- 重试保留已有条件、输入和成功部分。
- 没有真实进度时不伪造百分比。

## 组件状态

- **处理中**：说明正在发生什么并保留上下文。
- **部分成功**：分别呈现各结果范围并允许单独恢复。
- **结果未知**：阻止立即重复操作并提供确认路径。
