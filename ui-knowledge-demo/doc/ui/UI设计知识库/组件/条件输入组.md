# 条件输入组

> 让用户用已知特征逐步缩小对象范围，并理解当前条件。

**知识状态：** 候选规律　 **可信度：** 低

## 解决的问题

用与业务语言一致的条件控制结果范围，同时避免低频条件挤压主要内容。

## 适用场景

- 对象较多且用户只能提供部分特征。
- 结果范围会随多个条件反复变化。

## 不适用场景

- 用户已有唯一标识可直接到达对象。
- 对象很少且无需缩小范围。

## 在任务场景中的角色

- **条件查找与结果浏览**：作为查找任务的主要范围控制入口；出现条件：结果集合需要反复缩小时

## 与其他组件的组合关系

- 与 **[结果集合](../组件/结果集合.md)** 控制结果集合，并在更新时保留当前条件；条件：条件会直接改变结果范围时
- 与 **[状态反馈与恢复](../组件/状态反馈与恢复.md)** 把无匹配与请求失败反馈放在结果区域；条件：查询可能无结果或失败时

## 内容规则

- 优先展示高频且可理解的业务条件。
- 已生效条件应可识别、可清除。

## 布局规则

- 位于页面标题之后、结果集合之前。
- 低频条件按需展开，不长期占据主要结果空间。

## 交互规则

- 条件变化后应让用户理解结果为何变化。
- 重试时保留用户已经设置的条件。

## 组件状态

- **默认**：只展示最必要条件和默认范围。
- **已应用**：明确当前生效条件并支持局部清除。
