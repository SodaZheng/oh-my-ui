# 对象信息分组

> 按理解和判断顺序组织单个对象的核心信息、状态、历史与辅助依据。

**知识状态：** 候选规律　 **可信度：** 低

## 解决的问题

帮助用户先识别对象和关键信息，再按需深入辅助上下文。

## 适用场景

- 单个对象包含多个信息层次。
- 历史、关联或风险会影响判断。

## 不适用场景

- 只有一两个简单字段。
- 主要任务是横向比较多个对象。

## 在任务场景中的角色

- **单对象详情与状态处理**：承载对象核心详情和辅助上下文；出现条件：查看或处理单个复杂对象时
- **基于依据的审核与决定**：提供审核对象、依据和风险信息；出现条件：决定依赖多个信息来源时

## 与其他组件的组合关系

- 与 **[审核决定](../组件/审核决定.md)** 先提供判断依据，再出现决定行动；条件：页面承担审核与决定时

## 内容规则

- 对象身份、状态和关键差异优先。
- 辅助信息按使用频率和判断价值分组。

## 布局规则

- 核心信息占主要空间，历史和关联信息保持次要。
- 信息分组顺序遵循用户理解任务的先后。

## 交互规则

- 展开辅助信息后仍保持对象身份可识别。
- 信息更新后指出本次变化。

## 组件状态

- **只读**：以信息理解为主，行动保持次要。
