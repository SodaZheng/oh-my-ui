# 结果集合

> 承载多个对象的核心信息、比较线索和后续任务入口。

**知识状态：** 候选规律　 **可信度：** 低

## 解决的问题

让用户在一个稳定的主要区域中浏览、比较、选择并进入后续任务。

## 适用场景

- 需要同时理解一个以上对象。
- 对象之间存在可比较字段或状态。

## 不适用场景

- 任务只围绕单一对象展开。
- 对象必须按连续步骤逐个处理。

## 在任务场景中的角色

- **条件查找与结果浏览**：作为集合浏览页面的主要内容；出现条件：查找返回一个以上对象时
- **失败、部分成功与恢复**：按对象展示失败或未知结果；出现条件：异常需要对象级恢复时

## 与其他组件的组合关系

- 与 **[条件输入组](../组件/条件输入组.md)** 响应条件输入组并保持结果范围可解释；条件：集合由条件筛选得到时
- 与 **[任务行动](../组件/任务行动.md)** 为单对象或集合行动提供明确对象上下文；条件：结果支持后续处理时

## 内容规则

- 优先呈现识别、比较和判断所需的信息。
- 状态、风险和可执行性不能只靠位置或颜色表达。

## 布局规则

- 占据页面主要空间。
- 列、卡片或分组的选择取决于比较维度和信息密度。

## 交互规则

- 进入详情或执行行动时保留返回当前范围的路径。
- 结果更新不得丢失用户正在理解的上下文。

## 组件状态

- **加载**：保留结构预期并说明结果正在更新。
- **无结果**：保留条件并给出可调整方向。
- **失败**：与正常无结果区分并允许重试。
