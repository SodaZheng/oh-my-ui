# 分阶段信息录入

> 把信息量大或存在依赖的输入任务组织为可理解、可恢复的阶段。

**知识状态：** 候选规律　 **可信度：** 低

## 解决的问题

降低一次理解全部信息的负担，并保护未保存内容和提交完整性。

## 适用场景

- 输入存在明确分组或先后依赖。
- 中途离开会造成较高重复成本。

## 不适用场景

- 任务只修改一个简单值。
- 机械拆分会增加往返而没有理解收益。

## 在任务场景中的角色

- **分步骤创建与编辑**：承载当前阶段输入、进度和完整性检查；出现条件：创建或编辑任务较长时

## 与其他组件的组合关系

- 与 **[任务行动](../组件/任务行动.md)** 由任务行动承载返回、暂存、继续和最终提交；条件：输入存在阶段推进或提交时

## 内容规则

- 分组依据来自业务关系，不按字段数量机械切分。
- 说明和错误靠近对应输入。

## 布局规则

- 进度关系可见但不挤压当前输入空间。
- 当前阶段是主要内容，完整性反馈在推进或提交前出现。

## 交互规则

- 离开前保护未保存内容。
- 提交失败保留输入并指出可修复问题。

## 组件状态

- **未保存**：明确离开风险并提供保存或继续编辑选择。
