# 批量与异步处理

> 处理对象集合，或追踪无法即时完成的任务。

## 多对象批量处理与长任务跟踪

> 用户确认一组对象的范围和共同操作；任务无法即时完成时，可以离开并在之后回收结果。

**知识状态：** 候选规律　 **可信度：** 低

### 用户任务

减少重复处理，同时始终理解影响范围、执行进度和异常对象。

### 适用场景

- 多个对象执行相同操作。
- 用户能够确认选择范围和共同影响。
- 处理可能耗时较长或产生部分失败。

### 不适用场景

- 每个对象都需要不同输入或单独判断。
- 操作不可逆且无法清楚预览影响。
- 任务很轻且能够在原页面立即完成。

### 推荐页面形态与布局骨架

**独立任务处理空间。** 页面围绕选择范围、共同操作、影响确认和任务状态展开；提交后提供稳定的返回入口和结果摘要。

- 主布局方向：主布局方向待跨项目归并
- 主区域：主区域待跨项目归并
- 次要区域：次要区域待跨项目归并
- 区域关系待跨项目归并

页面从进入到主要内容的空间顺序：

1. 任务范围区：持续显示已选择对象数量、来源和排除项。
2. 共同操作区：只提供适用于全部所选对象的任务。
3. 影响与确认区：说明风险、不可处理对象和执行后果。
4. 执行状态区：显示受理、处理中、部分完成或中断。
5. 结果回收区：汇总成功、失败和仍需处理的对象。

### 功能组合

- **选择范围与共同操作**：保证用户知道谁将受到影响。 出现条件：从对象集合进入批量任务。
- **影响预览与风险确认**：在执行前暴露不可处理对象和后果。 出现条件：影响对象多或操作风险高。
- **任务身份与结果回收**：让用户离开后仍能找到任务和异常对象。 出现条件：任务不能即时完成。

### 组件搭配配方

- **必需 · [页面任务标题](../组件/页面任务标题.md)**：角色：识别批量任务和对象来源；位置：任务空间起始位置；理由：用户需要持续理解正在处理哪一组对象。
- **必需 · [批量范围与影响确认](../组件/批量范围与影响确认.md)**：角色：确认范围、共同操作和影响；位置：执行行动之前的主要区域；理由：批量操作必须先确认真实影响。
- **必需 · [任务行动](../组件/任务行动.md)**：角色：提交共同操作；位置：影响确认之后；理由：只有范围和风险明确后才可执行。
- **条件出现 · [状态反馈与恢复](../组件/状态反馈与恢复.md)**：角色：解释任务受理、进度和部分完成；位置：提交后的主要任务区域；条件：任务不能即时完成或可能部分失败时；理由：用户离开后仍需找回并处理异常对象。
- **避免 · [审核决定](../组件/审核决定.md)**：角色：不把统一批量操作当成逐对象审核；位置：不进入共同操作主流程；理由：每个对象需要单独判断时不应使用本场景。

### 完成任务的顺序

1. 确认对象范围
2. 选择共同操作
3. 理解影响和排除项
4. 提交并获得稳定任务入口
5. 查看进度与处理异常对象

### 关键状态

- **未选择对象**：不制造可执行假象，引导用户先确定范围。
- **已受理**：提供稳定任务标识和再次查看入口。
- **处理中**：没有真实进度时不伪造百分比。
- **部分完成**：分别说明成功、失败和仍在处理的对象。
- **中断**：说明已完成部分、未处理部分和是否可以继续。

### 设计边界

- 不能只显示总数而不说明选择来源和排除项。
- 长任务必须有离开后的稳定返回入口。
