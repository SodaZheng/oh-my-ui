# 创建与编辑

> 录入或修改信息，并安全地完成提交。

## 分步骤创建与编辑

> 用户分阶段录入或修改较多信息，在提交前理解完整性、影响和未保存内容。

**知识状态：** 候选规律　 **可信度：** 低

### 用户任务

可靠地完成一项信息量较大或存在依赖关系的创建与编辑任务。

### 适用场景

- 输入内容较多，存在明确分组或先后依赖。
- 中途离开会造成较高重复成本。
- 提交前需要检查完整性或影响。

### 不适用场景

- 只需修改一个简单值。
- 所有信息都能在一个短任务中完成。
- 用户只是在做是否通过的判断。

### 推荐页面形态与布局骨架

**单对象任务页。** 页面以当前编辑阶段为主，任务进度和对象上下文保持可见；次要说明靠近对应信息，提交行动位于流程末端。

- 主布局方向：主布局方向待跨项目归并
- 主区域：主区域待跨项目归并
- 次要区域：次要区域待跨项目归并
- 区域关系待跨项目归并

页面从进入到主要内容的空间顺序：

1. 任务与对象说明区：说明正在创建或修改什么。
2. 阶段关系区：让用户理解当前位置和剩余任务。
3. 当前内容区：集中完成当前阶段的输入与选择。
4. 完整性与影响区：在进入下一步或提交前指出缺失和后果。
5. 流程行动区：承载返回、暂存、继续和最终提交。

### 功能组合

- **分组输入与就近说明**：降低一次理解全部信息的负担。 出现条件：输入存在明确业务分组。
- **阶段进度与未保存保护**：防止迷失位置或意外丢失工作。 出现条件：任务跨多个阶段或成本较高。
- **提交前检查**：汇总缺失、冲突和提交影响。 出现条件：最终提交会改变业务状态。

### 组件搭配配方

- **必需 · [页面任务标题](../组件/页面任务标题.md)**：角色：识别创建或编辑任务；位置：页面内容起始位置；理由：用户需要持续知道正在修改什么。
- **必需 · [分阶段信息录入](../组件/分阶段信息录入.md)**：角色：承载当前阶段输入和完整性检查；位置：页面主要内容区；理由：信息量和依赖关系需要阶段化组织。
- **必需 · [任务行动](../组件/任务行动.md)**：角色：返回、暂存、继续和提交；位置：当前阶段末端或稳定行动区；理由：行动顺序应对应任务阶段和提交后果。
- **条件出现 · [状态反馈与恢复](../组件/状态反馈与恢复.md)**：角色：解释未保存、字段问题和提交失败；位置：对应输入附近及页面任务层；条件：输入不完整、离开或提交失败时；理由：保留输入并指出可修复问题。
- **避免 · [审核决定](../组件/审核决定.md)**：角色：不把信息补充表现为审核决定；位置：不进入编辑主流程；理由：任务目标是完成信息，而不是判断通过或驳回。

### 完成任务的顺序

1. 理解任务范围
2. 完成当前阶段信息
3. 处理缺失与冲突
4. 检查完整内容和影响
5. 提交并理解结果

### 关键状态

- **首次创建**：说明必要信息和整体完成路径。
- **已有内容编辑**：区分已有信息与本次变化。
- **存在未保存内容**：离开前明确风险并提供合适选择。
- **提交失败**：保留用户输入，指出可修复问题并支持重试。

### 设计边界

- 不要因为信息多就机械拆成过多阶段。
- 说明和错误应靠近对应内容，同时保留全局完整性反馈。
