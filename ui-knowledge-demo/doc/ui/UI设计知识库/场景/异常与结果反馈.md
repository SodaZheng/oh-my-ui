# 异常与结果反馈

> 解释空、失败、权限、部分成功和恢复路径。

## 失败、部分成功与恢复

> 当任务没有完整成功时，用户能够理解发生了什么、哪些内容受影响，以及如何安全继续。

**知识状态：** 候选规律　 **可信度：** 低

### 用户任务

在异常或不完整结果后恢复任务，而不重复成功部分或丢失必要输入。

### 适用场景

- 任务可能失败、部分成功或被中断。
- 用户可以重试、修正或继续处理。
- 结果会影响后续任务。

### 不适用场景

- 任务结果只需要短暂确认且没有后续行动。
- 系统无法判断成功范围时，不应伪造对象级结果。

### 页面整体形态

**结果与恢复空间。** 结果摘要首先说明总体发生了什么；异常范围和原因随后展开；恢复行动紧邻可恢复对象，同时保留返回上游任务的路径。

页面从进入到主要内容的空间顺序：

1. 结果摘要区：先说明总体成功、失败或部分完成。
2. 影响范围区：区分已完成、未完成和状态未知的对象。
3. 原因与处理建议区：解释用户可以理解并采取行动的原因。
4. 恢复行动区：提供重试、修正、继续或返回上游任务。

### 功能组合

- **结果级别与对象范围**：避免把部分成功误解为全部成功或全部失败。 出现条件：任务涉及一个以上对象或阶段。
- **可行动原因与恢复路径**：把技术异常翻译成用户能够处理的下一步。 出现条件：用户仍有补救空间。
- **上游任务返回关系**：恢复完成后继续原始工作。 出现条件：异常来自查找、编辑、审核或批量任务。

### 组件搭配配方

- **必需 · [状态反馈与恢复](../组件/状态反馈与恢复.md)**：角色：解释总体结果、影响范围、原因和恢复路径；位置：异常页面或受影响区域的主要位置；理由：恢复任务的前提是理解真实结果范围。
- **条件出现 · [结果集合](../组件/结果集合.md)**：角色：逐对象展示失败和未知结果；位置：结果摘要之后；条件：异常涉及多个可分别处理的对象时；理由：用户需要区分已完成和待恢复对象。
- **条件出现 · [任务行动](../组件/任务行动.md)**：角色：重试、修正、继续或返回；位置：可处理原因与对象附近；条件：用户仍有安全恢复路径时；理由：行动必须作用于明确的失败范围。
- **避免 · [分阶段信息录入](../组件/分阶段信息录入.md)**：角色：不强迫用户重新完成整套输入；位置：不覆盖已成功或已保留内容；理由：恢复应避免重复成功部分和丢失必要输入。

### 完成任务的顺序

1. 理解总体结果
2. 确认受影响范围
3. 查看可处理原因
4. 选择重试、修正或继续
5. 返回原始任务确认最终状态

### 关键状态

- **全部失败**：保留必要输入和范围，明确是否适合重试。
- **部分成功**：成功内容不重复执行，失败内容可单独继续。
- **结果未知**：明确状态尚未确认，避免引导用户立即重复操作。
- **权限受限**：解释可见范围和可寻求帮助的方向。

### 场景关系

- 后续可能进入：条件查找与结果浏览、单对象详情与状态处理
- 常与以下场景组合：分步骤创建与编辑、基于依据的审核与决定、多对象批量处理与长任务跟踪

### 设计边界

- 不知道结果时不能表现成失败或成功。
- 恢复行动必须避免重复已经成功的部分。
