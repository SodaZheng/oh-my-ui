# 审核与决策

> 基于上下文和风险依据做出可追溯判断。

## 基于依据的审核与决定

> 用户结合对象信息、风险和历史依据做出通过、退回或其他可追溯决定。

**知识状态：** 候选规律　 **可信度：** 低

### 用户任务

在信息充分且后果明确的情况下完成一次业务判断。

### 适用场景

- 决定会改变对象状态或影响后续流程。
- 判断需要参考多个信息来源。
- 决定结果需要留下理由或可追溯记录。

### 不适用场景

- 只是低风险的个人偏好选择。
- 用户缺少做决定所需的上下文。
- 任务本质是补充信息而不是判断。

### 页面整体形态

**单对象任务页。** 页面让审核对象、关键依据和风险先被理解；决定行动集中在稳定位置，理由与结果紧邻行动流程。

页面从进入到主要内容的空间顺序：

1. 审核对象与当前状态区：确认正在判断什么以及所处阶段。
2. 关键依据区：优先呈现直接影响判断的信息。
3. 补充上下文区：提供历史、关联记录和风险说明。
4. 决定与理由区：完成选择、说明理由并理解影响。
5. 结果反馈区：确认状态变化和后续流向。

### 功能组合

- **判断依据与风险提示**：把影响决定的信息置于行动之前。 出现条件：决定具有业务后果。
- **决定、理由与影响说明**：让选择可理解、可追溯。 出现条件：团队要求记录判断依据。
- **决定后的状态反馈**：说明对象的新状态和下一处理方。 出现条件：决定提交成功。

### 组件搭配配方

- **必需 · [页面任务标题](../组件/页面任务标题.md)**：角色：识别审核对象和当前阶段；位置：页面内容起始位置；理由：决定前必须确认对象与状态。
- **必需 · [对象信息分组](../组件/对象信息分组.md)**：角色：提供关键依据、历史和风险；位置：决定区域之前的主要内容；理由：判断必须建立在充分上下文上。
- **必需 · [审核决定](../组件/审核决定.md)**：角色：承载决定、理由和影响说明；位置：依据之后的稳定任务区；理由：决定与依据形成清晰阅读和操作顺序。
- **条件出现 · [状态反馈与恢复](../组件/状态反馈与恢复.md)**：角色：解释依据不足、状态冲突和决定结果；位置：受影响区域及决定区域附近；条件：无法决定、提交冲突或决定完成时；理由：用户需要理解为什么不能继续或对象流向哪里。
- **避免 · [分阶段信息录入](../组件/分阶段信息录入.md)**：角色：不把审核决定稀释成长表单录入；位置：不替代依据与决定关系；理由：任务核心是判断，补充信息只能作为必要辅任务。

### 完成任务的顺序

1. 确认审核对象和阶段
2. 阅读关键依据
3. 查看必要历史与风险
4. 做出决定并说明理由
5. 确认结果和后续流向

### 关键状态

- **待审核**：突出关键依据和当前可执行决定。
- **依据不足**：明确缺少什么，不迫使用户做无依据决定。
- **决定冲突**：说明对象状态已变化并要求重新确认。
- **决定完成**：展示新状态、记录结果和后续流向。

### 场景关系

- 后续可能进入：单对象详情与状态处理、失败、部分成功与恢复
- 常与以下场景组合：分步骤创建与编辑

### 设计边界

- 决定行动不能先于关键依据出现。
- 不同后果的决定需要分别说明影响，不能只改变行动文字。
