# 查找与结果浏览

> 缩小对象范围、理解结果并进入后续任务。

## 条件查找与结果浏览

> 用户通过已知条件缩小对象范围，理解结果概况，并继续查看或处理。

**知识状态：** 候选规律　 **可信度：** 低

### 用户任务

从较多业务对象中找到需要关注或处理的对象。

### 适用场景

- 对象数量较多，用户只能提供部分条件。
- 用户需要反复调整范围并比较结果。
- 结果集合是后续任务的入口。

### 不适用场景

- 用户已经拥有唯一标识，可以直接到达对象。
- 对象很少且无需查找。
- 主要任务是连续录入或分阶段处理。

### 页面整体形态

**集合浏览工作台。** 页面以结果区域为主体；任务名称和主要行动在上方，常用条件紧随其后，结果概况连接条件与主要内容。

页面从进入到主要内容的空间顺序：

1. 任务识别区：说明当前在查找什么，并放置页面级主要行动。
2. 条件区：保留高频条件，低频条件按需展开。
3. 结果概况区：解释当前范围、结果数量和选择状态。
4. 结果浏览区：占据主要空间，支持理解、比较和进入后续任务。
5. 范围延续区：在结果较多时帮助用户继续浏览并保持当前位置。

### 功能组合

- **常用条件组合**：用最少的高频条件快速缩小范围。 出现条件：用户通常知道对象的一部分特征。
- **结果概况与当前范围**：让用户知道结果为何变化。 出现条件：条件或选择发生变化。
- **结果比较与任务入口**：理解对象差异并进入单对象或集合处理。 出现条件：返回一个以上结果。

### 组件搭配配方

- **必需 · [页面任务标题](../组件/页面任务标题.md)**：角色：识别当前查找任务；位置：页面内容起始位置；理由：先建立范围和页面级行动认知。
- **必需 · [条件输入组](../组件/条件输入组.md)**：角色：控制结果范围；位置：任务标题之后、结果之前；理由：用户需要反复用已知条件缩小对象集合。
- **必需 · [结果集合](../组件/结果集合.md)**：角色：承载浏览、比较和后续入口；位置：页面主要内容区；理由：结果集合是任务主体。
- **条件出现 · [任务行动](../组件/任务行动.md)**：角色：进入创建或集合处理；位置：任务标题区或结果对象附近；条件：用户有后续处理权限时；理由：行动位置要与影响范围对应。
- **条件出现 · [状态反馈与恢复](../组件/状态反馈与恢复.md)**：角色：解释加载、无结果和失败；位置：受影响的结果区域；条件：结果尚未返回、无匹配或请求失败时；理由：不同结果状态需要保留条件并给出不同下一步。
- **避免 · [分阶段信息录入](../组件/分阶段信息录入.md)**：角色：不把查找拆成分阶段录入；位置：不进入集合浏览主流程；理由：查找依赖反复调整和即时比较，不是连续录入任务。

### 完成任务的顺序

1. 理解当前查找任务
2. 设置或调整条件
3. 确认结果范围
4. 浏览与比较对象
5. 进入单对象或集合处理

### 关键状态

- **初始**：展示最必要的条件，并说明默认结果范围。
- **正在更新**：条件保持可见，结果区域明确正在变化。
- **条件无结果**：保留当前条件并提示可调整方向。
- **请求失败**：与正常无结果区分，允许在保留条件的情况下重试。

### 场景关系

- 后续可能进入：单对象详情与状态处理、多对象批量处理与长任务跟踪
- 常与以下场景组合：失败、部分成功与恢复

### 设计边界

- 不要让低频条件长期挤压主要结果区域。
- 结果变化后必须让用户理解当前范围。
