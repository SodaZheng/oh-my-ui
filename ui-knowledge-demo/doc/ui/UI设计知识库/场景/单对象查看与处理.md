# 单对象查看与处理

> 围绕一个对象理解信息、状态、历史与可执行任务。

## 单对象详情与状态处理

> 用户围绕一个对象理解核心信息、当前状态、历史和关联上下文，并继续处理。

**知识状态：** 候选规律　 **可信度：** 低

### 用户任务

在完整理解对象后完成查看、修改、审核或后续任务。

### 适用场景

- 一个对象包含多个信息分组。
- 可执行行动取决于对象状态或用户权限。
- 历史、关联信息或风险会影响判断。

### 不适用场景

- 只需查看一两个简单字段。
- 用户需要横向比较多个对象。
- 主要任务是长时间批量处理。

### 推荐页面形态与布局骨架

**单对象任务页。** 对象身份、状态和主要行动首先可见；核心详情占主空间，历史、关联和风险作为辅助上下文出现。

- 主布局方向：主布局方向待跨项目归并
- 主区域：主区域待跨项目归并
- 次要区域：次要区域待跨项目归并
- 区域关系待跨项目归并

页面从进入到主要内容的空间顺序：

1. 对象识别区：显示对象身份、当前状态和返回关系。
2. 主要行动区：只展示当前状态和权限下可执行的关键行动。
3. 核心详情区：按理解顺序组织主要业务信息。
4. 辅助上下文区：提供历史、关联对象、风险和判断依据。
5. 状态反馈区：解释当前任务结果和下一步。

### 功能组合

- **对象身份与状态**：避免用户在错误对象或错误状态下行动。 出现条件：进入对象页面后始终存在。
- **分组详情与辅助依据**：先理解核心信息，再按需查看历史和关联。 出现条件：对象信息超过一个理解层次。
- **状态相关行动**：根据对象状态和权限提供可执行任务。 出现条件：用户具有相应权限且对象允许处理。

### 组件搭配配方

- **必需 · [页面任务标题](../组件/页面任务标题.md)**：角色：识别对象、状态和返回关系；位置：页面内容起始位置；理由：避免在错误对象或状态下行动。
- **必需 · [对象信息分组](../组件/对象信息分组.md)**：角色：组织核心详情和辅助依据；位置：页面主要内容区；理由：单对象任务需要分层理解多个信息来源。
- **条件出现 · [任务行动](../组件/任务行动.md)**：角色：执行对象当前允许的任务；位置：标题区或对应信息区域；条件：用户具备权限且对象状态允许时；理由：行动必须与对象状态和影响范围绑定。
- **条件出现 · [状态反馈与恢复](../组件/状态反馈与恢复.md)**：角色：解释权限、不存在和更新结果；位置：受影响区域或页面任务层；条件：内容或行动无法正常提供时；理由：保留可见上下文并给出真实原因。
- **避免 · [批量范围与影响确认](../组件/批量范围与影响确认.md)**：角色：不把单对象任务扩展为批量范围确认；位置：不进入单对象详情主结构；理由：当前任务只围绕一个明确对象。

### 完成任务的顺序

1. 确认对象身份与状态
2. 阅读核心详情
3. 按需查看历史和关联依据
4. 判断当前可执行任务
5. 进入编辑、审核或其他处理

### 关键状态

- **只读查看**：以理解信息为主，行动保持次要。
- **权限受限**：保留允许查看的信息，并解释行动为何不可用。
- **对象不存在**：区分不存在、已移除和无权访问。
- **信息更新后**：明确哪些内容已变化以及当前对象状态。

### 设计边界

- 对象身份和状态不能被大量详情淹没。
- 辅助上下文不应与核心详情争夺主要空间。
