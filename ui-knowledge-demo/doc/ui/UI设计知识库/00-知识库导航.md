# UI 设计知识库导航

> 这是分层结构演示，不是从真实项目源码扫描得到的正式规范；全部内容均为低可信候选知识。

这份知识库使用“组件能力 → 场景配方 → 页面蓝图”三层结构。页面蓝图从整体到局部还原真实页面，场景解释为什么这样组合，组件规范说明每种设计组件何时使用。

## 从真实页面开始

- [对象集合浏览页](页面/对象集合浏览页.md)：一个从任务识别、条件控制到结果浏览和后续处理的集合工作台示例。

## 从场景开始

- [查找与结果浏览](场景/查找与结果浏览.md)：缩小对象范围、理解结果并进入后续任务。
- [单对象查看与处理](场景/单对象查看与处理.md)：围绕一个对象理解信息、状态、历史与可执行任务。
- [创建与编辑](场景/创建与编辑.md)：录入或修改信息，并安全地完成提交。
- [审核与决策](场景/审核与决策.md)：基于上下文和风险依据做出可追溯判断。
- [批量与异步处理](场景/批量与异步处理.md)：处理对象集合，或追踪无法即时完成的任务。
- [异常与结果反馈](场景/异常与结果反馈.md)：解释空、失败、权限、部分成功和恢复路径。

## 从组件开始

- [页面任务标题](组件/页面任务标题.md)：说明用户当前位于哪里、正在完成什么任务，以及页面级状态和行动。
- [条件输入组](组件/条件输入组.md)：让用户用已知特征逐步缩小对象范围，并理解当前条件。
- [结果集合](组件/结果集合.md)：承载多个对象的核心信息、比较线索和后续任务入口。
- [任务行动](组件/任务行动.md)：承载页面级或区域级的主要、次要和高风险行动。
- [对象信息分组](组件/对象信息分组.md)：按理解和判断顺序组织单个对象的核心信息、状态、历史与辅助依据。
- [分阶段信息录入](组件/分阶段信息录入.md)：把信息量大或存在依赖的输入任务组织为可理解、可恢复的阶段。
- [审核决定](组件/审核决定.md)：让用户基于充分依据做出有后果、可追溯的业务决定。
- [批量范围与影响确认](组件/批量范围与影响确认.md)：持续解释哪些对象将被共同处理、哪些被排除以及操作后果。
- [状态反馈与恢复](组件/状态反馈与恢复.md)：解释处理中、无内容、失败、权限、部分成功和结果未知，并提供安全的下一步。

## 如何理解可信度

- 正式规范：团队已经明确确认，可约束后续设计。
- 候选规律：从既有页面归纳而来，需要继续验证或确认。
- 现状观察：只说明当前页面是什么样，不代表以后必须这样设计。
- 限定例外：只在文中写明的条件下覆盖一般规则。
